## 核心判断

建议保留当前目录的“评测对象主轨 + 资源类型”，将风险领域、攻击或失效机制、应用场景和评测协议拆为独立标签轴。当前 `topic` 本来只是导航主题，不应直接升级为互斥安全风险分类。

我们的白皮书文本与配套机器分类采用 8 个一级维度、19 个二级类型。这个基线值得保留用于历史结果对照，但其中的“恶意使用”“攻击鲁棒性”“自主人工智能安全”分别描述动机、机制和系统形态，与隐私、偏见等风险领域不在同一分类轴。

本轮已从全国网络安全标准化技术委员会官网核验：**《人工智能安全治理框架3.0》于 2026-09-14 发布**，包括内生、应用、衍生三类风险，以及专门的智能体风险管理附件。不能继续将 2.0 当作当前已核验的最新版本。它是治理框架，不是带 GB 编号的国家标准。

旧分类的条款映射需要独立审计：若“国标”指 GB/T 45654—2025，其资料性附录 A 只有 A.1–A.5，A.5 只有 a)、b)；旧 T15/T16 使用的“A.5 d”和 T17 使用的“A.6”不能由该标准支持。

## 方案边界

- 本文件提出本项目的综合分类方案，不宣称任何机构正式发布了相同的类别树。
- 国家标准、治理框架、法律、研究分类学和工程漏洞清单分别记录，不能相互替代。
- 风险标签表示资源覆盖目标，不表示模型已经造成现实伤害，也不表示资源已运行复现。
- 当前正式目录及历史数据不在本轮研究中自动重标；后续迁移需保留原标签、来源版本和人工裁决记录。

## 一、调研方法与证据边界

本轮采用“内部基线审计 → 官方标准与框架比对 → 研究分类学补缺 → 现有资源实例检验”的方式。来源优先级是标准发布机构、官方报告、作者仓库；不以搜索摘要或二手转载确认具体条款。研究结果是一套面向 **benchmark／资源目录覆盖目标** 的分类，而非完整合规认证体系，也不是把模型的安全表现压成一个总分。

自己的白皮书以本地《大模型安全评测白皮书-V1.0.docx》为本轮基线，共提取1,882段正文/XML文本；不将其称作最新最终版。正文的8一级／19二级与配套 JSON 对照，前言另使用六个概念，后续应统一口径。[S01](#s01)[S16](#s16) 另一份本地《人工智能白皮书.pdf》实际标题为《生成式人工智能网络安全等级保护与检测技术白皮书》，属于外部技术材料，已优先复用三份 MinerU HTML；不能混作我们的八维白皮书。[S15](#s15)

维护者本地保留网页、PDF、提取文本、SHA-256、抓取状态和 PDF preflight 结果，以及内部原件与白皮书段落的定位记录。本仓库公开来源编号、已审范围、可用的官方入口与缓存哈希；内部白皮书、原始机器路径、完整标准文件和本地缓存未随仓库分发。内部来源的内容无法仅凭本仓库独立复核，使用时应说明这一限制。

**已知限制：** 这是定向证据调研，未进行可声称穷尽的系统综述。GB/T 45654和46800的本地PDF可读，但preflight结果为 `UNAVAILABLE`（xref对象完整性检查未能给出通过结论），不是 `PASS`，也不是内容读取失败；因此主要按章节与条款引用。框架3.0、智能体指南草案和NIST AI 600-1的preflight为 `PASS`。英国采标仅核验BSI官方摘要，没有获得付费全文；不能据此构造具体附录控制项。ISO/IEC 23894:2023官方正文访问受限，本轮不把它作为已核验条款证据。

## 二、现有目录与白皮书分类的诊断

### 2.1 当前目录已经有正确的基础分层

`docs/taxonomy.md`明确区分主轨和资源身份，`topic`仅是主要导航主题。建议保留：

| 主轨 | 测什么 | 必须保留的边界 |
|---|---|---|
| `llm_safety` | 回答、拒答、内容判断和模型／应用行为 | 多轮对话不自动等于Agent端到端执行 |
| `agent_safety` | 工具使用、多步行动、环境状态变化 | 合成工具、LM模拟、有状态沙箱和真实外部动作分别记录 |
| `safety_judging` | 对既有内容、计划、下一动作或轨迹判断风险 | 判断正确不等于执行中的Agent安全 |
| `related_resources` | 攻击、训练、能力基线、诊断和补充资源 | 资源类型与安全风险分类分别记录 |

截至目录统计文件2026-10-15版本，共212个条目：143个`listed`、58个`related`、11个`needs_review`；143个listed中，LLM102、Agent30、judging11。公开展示的201项=143+58，不能写成201个独立benchmark。来源导入的692行含重复视图，不能充当独立资源数。以上仅来自本项目`data/stats.json`，与历史大规模样本库分母无关。

### 2.2 主要问题是不同分类轴混在同一层

| 当前或历史标签 | 实际回答的问题 | 优化处理 |
|---|---|---|
| 隐私、公平、有害内容 | 伤害或风险发生在哪里 | 放在风险领域 |
| jailbreak、prompt injection | 如何攻击／为何失效 | 放在机制轴 |
| 恶意使用 | 谁以何种动机使用系统 | 放在主体／意图轴，unknown必须允许 |
| agent、MCP、GUI、具身 | 通过什么系统和环境发生 | 放在系统形态与环境轴 |
| overrefusal、risk recognition | 测量的行为目标是什么 | 放在测量目标轴 |
| agent trajectory | 输入证据和评测协议是什么 | 放在协议轴，区分静态判读与动态执行 |
| 违法、价值观、政策合规 | 依据什么规范作判断 | 用带版本与法域的profile，并按实际内容叠加风险标签 |

如果将这些标签强行互斥，一个“提示注入导致Agent外传客户数据”的任务只能归入越狱、Agent或隐私之一，信息必然丢失。合理记录应同时表达：Agent执行、间接提示注入、个人数据外传、权限控制失守和具体执行环境。

### 2.3 三个容易影响结论有效性的旧问题

1. **旧国标映射无标准号与版本。** T15/T16引用“国标A.5 d”、T17引用“国标A.6”。若指GB/T 45654—2025，正式附录A仅有A.1–A.5，A.5仅a/b，不存在上述条款。这是引用有效性问题，应先修证据。[S02](#s02)[S16](#s16)
2. **有的二级范围过宽。** T1同时涵盖商业秘密、个人医疗／生物特征以及企业漏洞，不能由商业违法违规A.3统一支持；T16将幻觉纳入稳定性，与T10重叠。[S02](#s02)[S16](#s16)
3. **测量目标可能被过度解释。** T19中的“识别测试环境”并不独立证明有害欺骗；格式错误、普通能力不足和危险知识选择题正确，也不能自动解释为实际危险行为。[S01](#s01)[S16](#s16)[E03](#e03)

| S15 | 外部《生成式人工智能网络安全等级保护与检测技术白皮书》 | 复用现有三份MinerU HTML | 数据、模型、系统与应用的检测／控制链路 | 不能当作我们的白皮书或国家标准 |

**国外国家标准的版本核验：** BSI官方页明确，BS EN ISO/IEC 42001:2026是ISO/IEC 42001:2023的英国及欧洲采标，与原BS ISO/IEC 42001:2023在要求和指南上无技术差异；旧页写明2026版替代2023版。因此引用英国版本时应锁定2026版，不能未经核验继续称英国2023版为最新。本轮仅使用公开摘要支持“管理体系层”，不把它伪装成危害分类依据。[S14](#s14)

**为何不直接选一套原样照搬？** 中国服务基本要求关注服务内容与管理，框架3.0覆盖更广的AI系统风险；NIST把伤害、交互和集成来源同时纳入，MIT又区分因果与领域。它们服务的决策对象不同。我们的综合体系应记录映射关系，而不是宣称所有来源支持同一棵树。

## 四、推荐结构：主轨＋风险领域＋独立标签轴

### 4.1 最小可用字段

| 轴 | 例子 | 标注要求 |
|---|---|---|
| 评测对象主轨 | LLM、Agent、安全裁判、相关资源 | 保留当前主轨；混合套件可记录次级对象 |
| 资源身份 | benchmark、suite、dataset、attack、framework | 保留现有`resource_type`与父子关系 |
| 风险领域 | 隐私、网络安全、身心健康等 | 多标签；以实际任务／测量范围为证据 |
| 攻击／失效机制 | 越狱、间接注入、投毒、目标偏移、监督规避 | 与风险领域分开；攻击目标未知时不猜风险 |
| 主体与意图 | 人类攻击者、AI行为主体；有意／无意／未知 | 分主体记意图，不能把攻击者意图当模型意图 |
| 场景与系统形态 | 医疗、金融、GUI、MCP、多Agent、具身 | 行业、模态、语言、工具、自治程度分字段 |
| 协议与环境 | MCQ、生成回答、静态判轨迹、动态执行、社会影响研究；LM模拟／沙箱等 | 资源所声称协议与本项目已复现状态分开 |
| 测量目标 | 危险顺从、过拒、识别、可控性、效用 | 安全性和正常任务效用分别给分母 |
| 生命周期与影响层级 | 数据／训练／部署／运行／下线；个体／组织／社会 | 不强行归入内容标签 |
| 规范profile | `CN-GBT45654-2025:A.1(a)`等 | 带版本、条款、适用范围及映射关系 |

严重性、可逆性、发生可能性、受影响人数和评测证据强度可进一步扩展，但应与类别分开。“生物”“Agent”“违法”都不能直接换算统一严重性。可依框架3.0附件1记录场景、智能化水平、应用规模等分级背景；本轮不凭空设定统一高／中／低阈值。[S03](#s03)

### 4.2 候选风险领域：12个一级、39个二级

**以下数量是本项目的设计选择，状态为待验证，不是任何一份标准发布的12/39分类。** 一级表达相对稳定的危害或安全利益领域，二级提高检索和标注分辨率；允许多标签，主要任务是减少跨轴混淆，不承诺领域严格互斥。完整定义见[候选分类阅读页](taxonomy-proposal.md)，机器定义、纳入／排除规则见[候选 JSON](taxonomy-proposal-v0.1.json)。具体数量的形成过程与局限见[设计依据](taxonomy-rationale.md)。

| ID | 一级领域 | 二级类型 | 纳入边界与主要排除 | 主要依据 |
|---|---|---|---|---|
| D01 | 暴力、犯罪与公共安全 | .1人身暴力与一般武器；.2恐怖主义与暴力极端化；.3非数字犯罪与违禁活动协助 | 关注有害协助、煽动、实施与暴力内容暴露；CBRN转D07，数字入侵转D06，诈骗和IP转D08；法域政治表达不自动推定暴力 | S02、S03、S07、S10、S11 |
| D02 | 身心健康与自伤 | .1自伤自杀与危机应对；.2医疗心理建议与健康决策伤害；.3危险行为与物质滥用 | 单列自伤和不当健康建议；医学普通知识不自动等于健康危害评测，伤害他人暴力转D01 | S02、S06、S07、S11 |
| D03 | 性安全、剥削与儿童保护 | .1儿童性剥削与性化伤害；.2非自愿性内容与性犯罪协助；.3露骨性内容与年龄适宜性 | 区分儿童剥削、非自愿侵害、成人露骨内容政策；性教育和求助不因关键词被归为有害 | S02、S07、S11 |
| D04 | 歧视、公平与人格尊严 | .1群体歧视与表现不公平；.2仇恨、去人格化与污名；.3骚扰欺凌与侮辱 | 明确群体、评价对象及不公平构念；一般能力差距需要说明安全关联，身份提及不等于偏见 | S02、S03、S07、S09、S11 |

### 4.3 为什么保留这些看似可以合并的领域

- **自伤与一般暴力分开：** 面向自身危机的支持性应答、健康建议和对他人的暴力协助有不同判据；一律拒绝可能伤害求助者。[S07](#s07)[S11](#s11)
- **儿童剥削与成人露骨内容分开：** 前者与年龄、同意、剥削的判定有关，后者存在更强的受众和政策差异；不可只做“色情”单标签。[S11](#s11)
- **CBRN与一般有害内容分开：** 需要区分知识代理、能力提升和操作结果，不能仅用内容毒性评分。[S07](#s07)[S10](#s10)[E03](#e03)
- **人机交互与事实性分开：** 过度依赖、情感操纵和不当说服并不以事实错误为必要条件。[S07](#s07)[S09](#s09)[S10](#s10)
- **可控性与Agent身份分开：** 授权、目标、监督和可中断性是安全属性，Agent是系统形态；静态轨迹可测识别，动态执行可测约束是否保持。[S03](#s03)[S04](#s04)[S12](#s12)[E02](#e02)
- **社会环境保留独立检索：** 不因现有目录对此类benchmark稀少，就从理论分类中删除；但若只是影响综述，应保持相关资源身份。[S06](#s06)[S07](#s07)[S09](#s09)

### 4.4 必须写进标注手册的边界规则

1. **按评测构念标标签，不按标题关键词。** 先写清任务输入、要求的行为、失败判据、被保护利益和评分方式，再决定风险标签。
2. **一条记录可以只有机制标签或规范profile。** 例如未限定攻击目标的通用越狱方法，风险领域可保持unknown；不强塞“有害内容”。
3. **知识、内容、计划、行动、现实影响分开。** 可用性和构念证据不同，不能跨层宣称已验证。
4. **意图按主体记录。** 人类故意注入与模型无意执行可同时存在；不能写成“模型恶意”。
5. **误拒与漏拒成对报告。** `overrefusal`是测量目标，通常不是独立伤害领域。无害医学、性教育和身份相关问题尤其需要正常回答对照。[S02:B.1.3][E04](#e04)
6. **一般能力失误不自动纳入安全。** 格式错误、工具使用失败、幻觉需说明与安全约束或危害构念的关系；能力诊断可保留为related。
7. **任务级证据不自动继承到套件全部样本。** 套件可标覆盖并集，但每个子任务只能继承自身有证据的标签。
8. **“未测”不等于“安全”。** unknown、待审、无证据和不适用必须区分，不能合并成False。
9. **不把反事实人格描述当观察行为。** “我有隐瞒意图”的自述、选择某价值选项、识别测试状态，与实际规避监督、隐瞒工具链是不同证据。
10. **严重性不从类别名推定。** 同一CBRN标签可对应普通知识代理或高后果执行；同一Agent标签也可只有静态判题。

## 八、如何证明这套分类可用

### 8.1 先做分层试标，再确定二级边界

**以下是建议实验设计，不是已执行结果，也不是标准规定的样本量。**

1. 从当前目录选择约30–40个资源，按LLM／Agent／裁判、内容／知识代理／静态轨迹／动态执行、中文／外语／多模态分层；单独覆盖机制型资源、混合套件和`needs_review`边界资源。
2. 每个资源抽取可获得的2–5个任务组件或公开样本，形成约100–150个标注单元；若版权、访问或任务结构不允许，记录未取得，不用标题替代原任务证据。低频CBRN、儿童保护、环境影响等允许定向补样，单报抽样方式。
3. 两名标注者先独立写任务构念、证据定位和标签，再由第三人裁决；先用一小组争议案例修手册，再扩大试标。不能先批量接受模型重标结果，再补理由。
4. 本版JSON已为39个二级标签提供候选定义、边界与来源；试标阶段进一步补“必要证据／正例／近邻反例”，尚不能声称已完成可操作性验证。
5. 分析混淆对：D04.2与D04.3、D05.2与D08.3、D09与D10.2、D11与一般能力错误、D12与任务级内容指标，以及政策profile与通用危害。再判断39个二级是否需要合并或新增。

### 8.2 报哪些验证量

| 验证问题 | 建议报告 | 避免误读 |
|---|---|---|
| 同一个单元能否稳定标注 | 多标签集合完全一致率、Jaccard；按轴分别报告 | 明确空集合与unknown处理；不能把未知当全阴性 |
| 具体标签能否复现 | 各标签原始一致率、正例一致情况；对裁决参考集报告precision/recall/F1 | F1是对参考集的一致表现，不是真值的绝对证明；报告样本数与低频不确定性 |
| 风险域是否覆盖任务 | 无法归类比例、unknown／待审比例、需要新增标签的原因 | 未取得任务证据与taxonomy未覆盖分别统计 |
| 分层是否有实际价值 | 按协议、主轨、模态检查混淆和边界案例 | 不靠类别数更多证明更好 |
| 能否支持目录分析 | 资源级覆盖、任务级覆盖、父子重叠及去重计数 | 标签覆盖计数可大于独立资源数，不能相加作为benchmark总数 |

若补充Cohen's kappa等指标，应明确是逐标签二元计算、样本相关性和类别不平衡；不将单个kappa当唯一采用门槛。采用阈值需在试标前登记并结合误标代价制定，本轮不伪造“达标”或统一阈值。

### 8.3 实施顺序与统计合同

- **阶段A：候选登记。** 采用本报告与`0.1.0-proposal`，仅增加研究产物；保留当前正式目录。
- **阶段B：小样本裁决。** 锁定来源快照和标注粒度，完成手册与争议台账，发布试标结果及局限。
- **阶段C：正式版本。** 根据试标修订为稳定版本；通过sidecar或正式schema迁移，保留旧标签和双向追踪，更新网页筛选与统计脚本。
- **阶段D：持续维护。** 标准与数据版本更新触发映射复审；不让外部机构的术语变动静默改写历史结果。

资源数以去重后的资源／版本为分母，样本数以任务单元为分母，套件与组件不能重复相加。运行状态必须另记：链接可达、正文核验、数据下载、运行复现分别记录。不同协议分别汇总MCQ知识、内容应答、风险识别、行动约束和社会影响指标，不生成未经验证的跨协议安全总分。
